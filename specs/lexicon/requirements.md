# 独自lexicon 要件定義書

## 1. 目的

ユーザーが宣言するタスクと評価の回答を、AT Protocol の独自レコードとして定義し、Bot が発行する受理と結果の証明を Bot 側のレコードとして定義する。公開後はスキーマを変更しにくいため、互換性を壊さない構造と検証を最初から備える。

## 2. スコープ

### 2.1 対象

- ユーザーのリポジトリに置くタスクと回答の2種のレコード。
- Bot のリポジトリに置く受理と結果の2種のレコード。
- 結果の種別の列挙と、レコードの検証。
- 公開済みスキーマとの互換性検査。

### 2.2 対象外

- メンション投稿の解析と受理の判定手順。
- 返信文の解析による結果の判定。
- 画面の表示と入力。

## 3. 前提

- なし

## 4. 機能要件

- FR-1: タスクレコードは、内容・期限日・リマインド時刻・作成日時をすべて必須とする。
- FR-2: タスクの内容は1文字以上30文字以下とし、改行・制御文字・リンクやメンションを成す記号を含まない。
- FR-3: 期限日は日本時間の暦日を表す文字列とし、リマインド時刻は日本時間の0時からの分を0以上1439以下の整数で表す。
- FR-4: 回答レコードは、受理への参照・結果の種別・作成日時を必須とし、補足の文を200文字以下で任意とする。
- FR-5: 結果の種別は、できた・できなかった・一部できた・未評価を既知の値とし、未知の値を受け取っても読み取りを継続できる列挙とする。
- FR-6: 受理レコードは、持ち主の DID・起点への参照・内容・期限日・リマインド時刻・受理日時を必須とする。
- FR-7: 起点は、メンション投稿とその会話の根の投稿への参照か、ユーザーのタスクレコードへの参照のどちらかとし、参照は URI と CID を持つ。
- FR-8: 結果レコードは、受理への参照・結果の種別・判定の根拠への参照・確定日時を必須とし、未評価のときは根拠を省略できる。
- FR-9: タスクと回答はユーザーのリポジトリに、受理と結果は Bot のリポジトリにのみ置き、Bot 側のレコードは作成後に更新しない。
- FR-10: すべてのレコードの構造と意味規則を検証し、違反した項目と理由を返す。
- FR-11: 公開済みスキーマに対し、必須性・型・制約の変更を検出する互換性検査を提供する。

## 5. 非機能要件

- NFR-1: 1レコードの検証は5ミリ秒以内に完了する。
- NFR-2: 1レコードの JSON 表現は4キロバイト以下に収まる。

## 6. 受け入れ条件

- AC-1 (FR-1): 必須項目をすべて満たすタスクレコードは検証に成功し、必須項目が1つ欠けると失敗する。
- AC-2 (FR-2): 内容が30文字のタスクは成功し、31文字と改行を含む内容は失敗する。
- AC-3 (FR-2): 内容に @ や URL を含むタスクは失敗する。
- AC-4 (FR-3): 実在しない日付の期限日と、1440分以上のリマインド時刻は、どちらも失敗する。
- AC-5 (FR-4): 補足を省略した回答レコードは成功し、201文字の補足を持つ回答レコードは失敗する。
- AC-6 (FR-5): 結果の種別が未知の値である回答レコードの検証に成功する。
- AC-7 (FR-6): 持ち主の DID が欠けた受理レコードは検証に失敗する。
- AC-8 (FR-7): 起点が投稿と根の参照のものとタスクレコードの参照のものは成功し、両方を持つもの、どちらも持たないものは失敗する。
- AC-9 (FR-8): 結果の種別が未評価で根拠を省略した結果レコードは成功し、できたで根拠を省略したものは失敗する。
- AC-10 (FR-9): Bot 側の2種のレコードは、ユーザー側のレコードと異なる階層の識別子を持ち、更新日時の項目を持たない。
- AC-11 (FR-10): 違反のあるレコードの検証結果が、違反した項目名と理由コードを含む。
- AC-12 (FR-11): 公開済みスナップショットに対し、必須項目の追加と型の変更は検出され、任意項目の追加は検出されない。
- AC-13 (NFR-1): 検証を1000回実行した1回あたりの平均が5ミリ秒以下である。
- AC-14 (NFR-2): 全項目を上限の長さで埋めた各レコードの JSON が4キロバイト以下である。
