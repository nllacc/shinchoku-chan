# Webフォーム 要件定義書

## 1. 目的

メンションの定型に合わないときの登録と、返信で評価が伝わらなかったときの評価の入力を、Web フォームで行えるようにする。ユーザーは Bluesky のアカウントでサインインし、自分の PDS にタスクや回答のレコードを書く。サーバーはユーザーの認証情報を保持しない。

## 2. スコープ

### 2.1 対象

- ブラウザでの Bluesky の OAuth によるサインインとサインアウト。
- タスクの登録フォームと、受理の結果の表示。
- 評価の入力フォームと、受理の結果の表示。
- 登録のしかたを示すトップ画面。

### 2.2 対象外

- Web 画面でのタスクの一覧、変更、取り消し。
- 点数とランキングの表示。
- 返信文の解析。

## 3. 前提

- 前提: lexicon — 書き込むレコードの構造と検証を使う。
- 前提: ui-foundation — 基底部品と設計値を使う。

## 4. 機能要件

- FR-1: ユーザーは Bluesky のハンドルを入力して OAuth でサインインし、要求する権限は、タスクと回答のレコードの作成だけとする。
- FR-2: 再読み込み後もセッションを復元し、サインアウトでセッションを破棄できる。
- FR-3: タスクの登録フォームは、内容・期限日・リマインド時刻を入力でき、保存前に構造と意味規則を検証する。
- FR-4: 登録は、タスクレコードを自分の PDS に作ってから受理を依頼し、受理の結果か拒否の理由を日本語で表示する。
- FR-5: 受理の依頼に失敗したあと再実行しても、タスクレコードは2件作られない。
- FR-6: 評価の入力画面は、受理のキーから内容と期限日を表示し、評価済みの受理には入力欄を表示せず評価済みであることを示す。
- FR-7: 評価の入力フォームは、できた・できなかった・一部できたから1つを選び、補足を任意で入力でき、回答レコードを作ってから受理を依頼し、結果を表示する。
- FR-8: サインイン中のユーザーが受理の持ち主と異なるとき、入力欄を表示せず理由を示す。
- FR-9: 存在しない受理のキーでは、見つからないことを示す。
- FR-10: トップ画面は、メンションでの登録の書き方の例と、登録フォームへのリンクを表示する。

## 5. 非機能要件

- NFR-1: 画面のスクリプトは、圧縮後200キロバイト以下で配信する。

## 6. 受け入れ条件

- AC-1 (FR-1): サインインで要求される権限が、タスクと回答のレコードの作成だけである。
- AC-2 (FR-2): サインイン後に再読み込みしても、サインイン状態が保たれ、サインアウトで解除される。
- AC-3 (FR-3): 内容が31文字の入力と、実在しない期限日の入力は、保存前に拒否される。
- AC-4 (FR-4): 登録に成功すると、受理されたことが表示され、自分の PDS にタスクレコードが作られている。
- AC-5 (FR-4): 受理が拒否されると、期限の範囲外、時刻が近すぎる、同時進行数が上限、のそれぞれが日本語の理由で表示される。
- AC-6 (FR-5): 受理の依頼に失敗したあと再実行しても、作られたタスクレコードは1件のままである。
- AC-7 (FR-6): 受理のキーを開くと、内容と期限日が表示され、評価済みの受理では入力欄が表示されない。
- AC-8 (FR-7): 評価を選んで送信すると、回答レコードが作られ、受理の結果が表示される。
- AC-9 (FR-7): 補足が201文字の入力は、保存前に拒否される。
- AC-10 (FR-8): 受理の持ち主と別のユーザーでサインインしているとき、入力欄が表示されず理由が示される。
- AC-11 (FR-9): 存在しない受理のキーで、見つからないことが表示される。
- AC-12 (FR-10): トップ画面に、定型の例と登録フォームへのリンクが表示される。
- AC-13 (NFR-1): 画面のスクリプトの圧縮後の転送サイズが200キロバイト以下である。
