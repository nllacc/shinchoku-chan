# タスク受理 要件定義書

## 1. 目的

ユーザーが Bot へのメンションか Web フォームで宣言したタスクを受理し、Bot の PDS に受理の証明を残して、リマインドと評価依頼の計画を作る。登録の項目は期限日・リマインド時刻・内容の3つに絞り、ユーザーが一言で登録できるようにする。

## 2. スコープ

### 2.1 対象

- メンション投稿の定型の文からの、3項目の取り出し。
- フォームで作られたタスクレコードの受理。
- 受理の可否の判定、受理レコードの作成、受理の確認の投稿。
- リマインド・評価依頼・評価の期限切れの計画の生成と、計画の再構築。

### 2.2 対象外

- リマインドと評価依頼の投稿の実行。
- 返信文による結果の判定。
- 画面の表示。

## 3. 前提

- 前提: platform — 通知の受信、Bot の投稿、保存先、資格、日本時間を使う。
- 前提: lexicon — タスクと受理のレコードの検証を使う。

## 4. 機能要件

- FR-1: メンション投稿の本文から、「期限まで 時刻に 内容」の定型で期限日・リマインド時刻・内容を取り出す。
- FR-2: 期限は、月日・年月日・明日・あさって・N日後のいずれかで、時刻は、H時・H時M分・H時半・HH:MM のいずれかで書ける。
- FR-3: 定型に合わないメンションには、書き方の例と登録フォームの URL を返信する。
- FR-4: 期限日は受理の日から1日以上14日以内とし、最初の評価依頼の時刻が受理から30分以上先でなければ受理しない。
- FR-5: ユーザーの同時進行数が資格の上限に達しているときは受理せず、上限を伝える返信を送る。
- FR-6: フォームで作られたタスクレコードの URI を受け取り、公開レコードを CID 照合して取得し、検証して受理する。
- FR-7: 受理では、起点の URI から導いたキーで Bot の PDS に受理レコードを作る。
- FR-8: 受理の確認は、メンション経路ではメンション投稿への返信で、フォーム経路ではユーザーをメンションした新規投稿で伝える。
- FR-9: 受理ごとに、受理日から期限日の前日までの毎日のリマインドと、期限日の評価依頼と、評価の期限切れの計画を作る。
- FR-10: 各計画の時刻は、指定のリマインド時刻の前後10分の範囲で、計画ごとに固定の値だけずらす。
- FR-11: 同じ通知や同じレコードを再処理しても、受理レコード・計画・確認の投稿は増えない。
- FR-12: 運用者は、Bot の PDS の受理と結果のレコードから、未完了の計画を作り直すスクリプトを実行できる。

## 5. 非機能要件

- NFR-1: 受理1件が発生させる Bluesky への通信は、4回以内である。
- NFR-2: 定型の文の解析は、1件あたり1ミリ秒以内に完了する。

## 6. 受け入れ条件

- AC-1 (FR-1): 「10/25まで 18時に 資料作成」から、期限日 10/25・18時・内容「資料作成」が得られる。
- AC-2 (FR-2): 全角数字の「１０月２５日まで １８：３０に 掃除」から、期限日 10/25・18時30分・内容「掃除」が得られる。
- AC-3 (FR-2): 「明日まで 7時半に ゴミ出し」と「3日後まで 20:00に 洗濯」が、日本時間の暦日と時刻へ正しく変換される。
- AC-4 (FR-3): 定型に合わない文のメンションに対し、書き方の例とフォームの URL を含む返信が送られ、受理レコードは作られない。
- AC-5 (FR-4): 受理の日から15日後の期限と、評価依頼の時刻が受理から20分後になる期限は、どちらも受理されない。
- AC-6 (FR-5): 無料の上限が1の DID が進行中のタスクを1件持つとき、2件目は受理されず、上限を伝える返信が送られる。
- AC-7 (FR-6): フォームで作られたタスクレコードの URI から、CID が一致すれば受理され、一致しなければ拒否される。
- AC-8 (FR-7): 受理レコードが、持ち主の DID・起点の参照・内容・期限日・リマインド時刻を持ち、同じ起点からは同じキーで作られる。
- AC-9 (FR-8): メンション経路の確認が起点の投稿への返信になり、フォーム経路の確認がユーザーをメンションした新規投稿になる。
- AC-10 (FR-9): 10/22 の昼に期限 10/25・18時で受理すると、10/22 から 10/24 のリマインド3件と、10/25 の評価依頼1件と、期限切れ1件の計画ができる。
- AC-11 (FR-10): すべての計画の時刻が指定の時刻の前後10分以内で、同じ計画に対して常に同じ時刻になる。
- AC-12 (FR-11): 同じメンションの通知を2回処理しても、受理レコード・計画の行・確認の投稿はそれぞれ1件のままである。
- AC-13 (FR-12): 受理を3件、結果を1件持つ PDS に対し、スクリプトが未完了の2件分の計画だけを出力する。
- AC-14 (NFR-1): メンション経路の受理1件で、Bluesky への通信が4回以内である。
- AC-15 (NFR-2): 解析を1000回実行した1回あたりの平均が1ミリ秒以下である。
