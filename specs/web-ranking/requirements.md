# ランキング画面 要件定義書

## 1. 目的

サインインなしで、いつでもランキングを閲覧できる画面と、アプリ全体の枠組みを提供する。一覧は一部の情報だけを表示して見通しを保ち、選んだ行の詳細を重ねて表示する。

## 2. スコープ

### 2.1 対象

- ランキングの一覧、並べ替え、続きの読み込み。
- 行を選んだときの詳細の表示。
- アプリ全体のヘッダーと画面遷移。

### 2.2 対象外

- 評価の計算とランキングの取得処理。
- 作業の登録と報告の画面。

## 3. 前提

- 前提: ui-foundation — 基底部品と設計値を使う。
- 前提: platform — APIの共通の応答形式を使う。

## 4. 機能要件

- FR-1: 一覧は、ユーザー名、概要の冒頭、期間、評価点、最終進捗度を1行に表示する。
- FR-2: ユーザー名は、そのユーザーのBlueskyのプロフィールへのリンクにする。
- FR-3: 評価点と最終進捗度の列で、昇順と降順を切り替えられる。
- FR-4: 並べ替えの状態はアドレスに保持し、共有したリンクで同じ並びを再現できる。
- FR-5: 一覧は50件ずつ表示し、「さらに表示」の操作で続きを読み込む。
- FR-6: 行を選ぶと、詳細がダイアログで重なって表示され、閉じると一覧の位置と並びが保たれる。
- FR-7: 詳細は、ゴール、最終進捗度、評価点、欠測件数、概要の全文、結果の説明、期間を表示する。
- FR-8: 詳細に画像がある場合は、開始前と結果の画像を表示し、読み込めない画像は省略する。
- FR-9: 読み込み中、0件、取得失敗の各状態を表示し、失敗時は再試行できる。
- FR-10: ヘッダーに、ランキング・作業を始める・サインイン状態・テーマ切り替えを置く。
- FR-11: 画面幅360ピクセルでは、表を1行ごとのカード表示に切り替える。
- FR-12: 評価点は小数点以下2桁、最終進捗度は百分率で表示する。

## 5. 非機能要件

- NFR-1: ランキング画面の初回表示のスクリプトは、圧縮後120キロバイト以下で配信する。
- NFR-2: 一覧の初回表示は、取得の応答が300ミリ秒の場合に、アクセスから1.5秒以内に完了する。

## 6. 受け入れ条件

- AC-1 (FR-1): 一覧の各行に、ユーザー名・概要の冒頭・期間・評価点・最終進捗度が表示される。
- AC-2 (FR-2): ユーザー名を選ぶと、Blueskyのプロフィールのアドレスへ移動する。
- AC-3 (FR-3): 評価点の列を選ぶたびに、降順と昇順が切り替わり、表示の並びも変わる。
- AC-4 (FR-4): 最終進捗度の昇順にしたアドレスを開くと、同じ並びで表示される。
- AC-5 (FR-5): 51件以上あるとき「さらに表示」で続きが追加され、重複しない。
- AC-6 (FR-6): 行を選ぶとダイアログが開き、閉じると元の並びとスクロール位置に戻る。
- AC-7 (FR-7): 詳細に、ゴールと概要の全文と欠測件数が表示される。
- AC-8 (FR-8): 画像のある作業の詳細に画像が表示され、読み込めない画像は表示されない。
- AC-9 (FR-9): 取得に失敗したとき、エラーと再試行の操作が表示され、操作で再取得される。
- AC-10 (FR-9): 0件のとき、空の状態の案内が表示される。
- AC-11 (FR-10): ヘッダーの4つの要素が表示され、遷移が機能する。
- AC-12 (FR-11): 幅360ピクセルで、一覧がカード表示になり、横スクロールが発生しない。
- AC-13 (FR-12): 評価点8735は「87.35」、最終進捗度1000は「100%」と表示される。
- AC-14 (NFR-1): ランキング画面の初回表示のスクリプトを圧縮した転送サイズが120キロバイト以下である。
- AC-15 (NFR-2): 応答が300ミリ秒のとき、一覧がアクセスから1.5秒以内に表示される。
