# 実行基盤 要件定義書

## 1. 目的

Web 画面の配信、API、Bot の毎分の定期実行を、無料枠に収まる1つの実行基盤で提供する。ほかの機能が共通で使う保存先の契約、システムオプション、日本時間、PDS の読み取り、Bot の認証・通知の受信・投稿、プレミアム資格の引き当てをここにまとめる。保存先は PDS から再構築できる索引だけを持つ。

## 2. スコープ

### 2.1 対象

- 静的アセット、API、定期実行を提供する単一の Worker。
- 保存先の契約とその実装、システムオプション、プレミアム資格。
- 日本時間の扱いと、PDS の公開レコードの読み取り。
- Bot アカウントの認証、通知の受信と配信、投稿の作成、Bot が作るレコードのキーの導出。
- Bot の自己ラベルを確認する運用スクリプト。

### 2.2 対象外

- メンションの解析、リマインド、評価の個別の処理。
- 通知を受けた後の登録や評価の判断。
- 画面の表示。
- 課金の手続き。

## 3. 前提

- なし

## 4. 機能要件

- FR-1: 1つの Worker が、静的アセットの配信、共通の JSON 形式で応答する API、定期実行を提供し、エラーは種別・メッセージ・再試行可否を持つ。
- FR-2: 定期実行は毎分起動して登録された処理を登録順に実行し、処理が1つ失敗しても後続を実行して失敗を記録する。
- FR-3: システムオプションは、環境変数の値を優先し、なければ既定値を使い、型と範囲を検証する。
- FR-4: 日付と時刻は日本時間で扱い、期限日とリマインド時刻から実時刻を求められる。
- FR-5: ユーザーの PDS を解決して公開レコードを取得し、その CID を再計算して照合できる。
- FR-6: Bot は専用アカウントのアプリパスワードで認証し、取得したセッションを保存して再利用する。
- FR-7: プレミアム資格は DID の一覧で与え、同時に進行できるタスク数の上限を DID から引き当て、資格がなければ無料の上限を返す。
- FR-8: 計画・評価待ちの投稿・キー値の3種のデータを、保存先に依存しない契約を通して保存する。
- FR-9: Bot が作るレコードのキーは、秘密値と入力から同じ値を導き、二重の作成を拒否できる。
- FR-10: Bot 宛のメンションと返信の通知を毎分取得し、評価待ちの投稿への返信は回答として、それ以外のメンションは登録として、登録された処理へ渡す。
- FR-11: Bot の投稿は、メンションとリンクの facet と返信の参照を正しく付けて作成できる。
- FR-12: 運用者は、Bot アカウントのプロフィールに bot の自己ラベルが付いているかを、スクリプトで確認できる。

## 5. 非機能要件

- NFR-1: 定期実行の1回あたりの CPU 時間は、処理が空の場合に5ミリ秒以下である。
- NFR-2: 処理が空の定期実行が保存先から読む行数は、5行以下である。
- NFR-3: 保存先の契約の1操作が発生させる外部通信は、1回以内である。
- NFR-4: 通知は、相手の投稿から90秒以内に登録された処理へ渡される。

## 6. 受け入れ条件

- AC-1 (FR-1): 静的アセットのパス、API のパス、定期実行の呼び出しが、同じ Worker で処理される。
- AC-2 (FR-1): 失敗した API 応答が、種別・メッセージ・再試行可否を含む。
- AC-3 (FR-2): 登録した3つの処理が、登録順に1回ずつ呼び出される。
- AC-4 (FR-2): 2つ目の処理が失敗しても3つ目が実行され、失敗が記録される。
- AC-5 (FR-3): 環境変数がなければ既定値、あればその値が返り、範囲外の値は拒否されて既定値が返る。
- AC-6 (FR-4): 日本時間の深夜0時を日の境界とし、期限日 10/25 とリマインド時刻 18:00 から日本時間 18 時の実時刻が得られる。
- AC-7 (FR-5): 取得したレコードの CID を再計算した値が、PDS の返す CID と一致する。
- AC-8 (FR-5): 内容を改変したレコードは、CID が一致しないと判定される。
- AC-9 (FR-6): 有効なセッションがあれば再認証せず、期限が切れていれば更新し、更新に失敗したときだけ新規にログインする。
- AC-10 (FR-7): 一覧に含まれる DID は有料の上限、含まれない DID は無料の上限が返る。
- AC-11 (FR-8): 保存先の実装を差し替えても、同じ契約の試験がすべて成功する。
- AC-12 (FR-8): 同じ計画を2回登録しても、行は1件のままである。
- AC-13 (FR-9): 同じ秘密値と同じ入力から導いたキーは常に同じ値になり、入力が1つ違うと別の値になる。
- AC-14 (FR-10): 評価待ちの投稿への返信は回答の処理へ、評価待ちでない投稿への返信は無視され、メンションは登録の処理へ渡される。
- AC-15 (FR-10): 同じ通知を2回取得しても、登録された処理へ渡すのは1回だけである。
- AC-16 (FR-10): Bot 自身の投稿の通知は、どの処理にも渡されない。
- AC-17 (FR-11): 日本語の本文に付けたメンションとリンクの facet の範囲が、バイト単位で対象の文字列と一致する。
- AC-18 (FR-11): 返信の投稿は、会話の根と親の参照を持つ。
- AC-19 (FR-12): 自己ラベルが付いていないプロフィールに対し、スクリプトが終了コード1を返す。
- AC-20 (NFR-1): 処理が空の定期実行の CPU 時間が5ミリ秒以下である。
- AC-21 (NFR-2): 処理が空の定期実行が保存先から読む行数が5行以下である。
- AC-22 (NFR-3): 保存先の契約の各操作が、外部通信を1回以内で完了する。
- AC-23 (NFR-4): 通知が現れた1分後の定期実行で、その通知が登録された処理へ渡される。
