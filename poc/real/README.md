# 実アカウントでの受理フロー PoC

## 1. 結論

bsky.social 上の実アカウント 2 つ（ユーザーと Bot）で、起点投稿・作業・確認依頼・進捗報告・受領証の作成から、Worker での CID 照合、削除までが成功する。ブラウザの OAuth でも、要求した権限だけが付与され、要求していない操作は拒否される。公開 HTTPS に置いた Worker でも OAuth・CID 照合ができ、Bot の返信は通知とスレッドになる。

- receipt

## 3. 制約値

| 項目                                                           | 値                                                              |
| -------------------------------------------------------------- | --------------------------------------------------------------- |
| 実環境での受理 1 回の外部通信の所要時間（DID 解決）            | 約 500〜730 ミリ秒                                              |
| 実環境での受理 1 回の外部通信の所要時間（取得）                | 約 140〜550 ミリ秒                                              |
| 本番の Worker での受理 1 回の CPU 時間（DID 解決・取得・照合） | 2〜4 ミリ秒                                                     |
| createSession の回数                                           | 1 アカウントあたり 1 日 10 回                                   |
| refreshSession の回数                                          | 1 分あたり 60 回                                                |
| Bot のアクセストークンの有効期間                               | 120 分                                                          |
| Bot のリフレッシュトークンの有効期間                           | 90 日                                                           |
| OAuth のアクセストークンの有効期間                             | 約 1 時間                                                       |
| 書き込み・読み取りの制限（制限ヘッダ）                         | 5 分あたり 3000 点                                              |
| 新しい Bot アカウントに spam ラベルが付くまでの量              | 約 1 時間で返信 12 件の作成と削除（公式のモデレーションが付与） |
| 本番の Worker の外部通信の上限（無料枠）                       | 1 回の実行あたり 50 回                                          |
| 本番の Worker の D1 クエリの上限                               | 1 回の実行あたり 1000 回                                        |
| listRecords の 1 ページの最大件数                              | 100 件（101 件はエラー）                                        |
| PDS が受け付ける blob の大きさ                                 | 5.9 メガバイトを受理（1 メガバイトの上限は自前で検証）          |
| 書き込み直後の公開取得                                         | 約 250 ミリ秒で成功                                             |

## 4. 検証項目

| 仮説                                                                        | 合格基準                                                     | 結果 |
| --------------------------------------------------------------------------- | ------------------------------------------------------------ | ---- |
| 実 PDS 上の独自コレクションにユーザーと Bot がレコードを作成できる          | 作業・進捗報告・確認依頼・受領証の作成が成功する             | 合   |
| Bot が起点投稿へ返信できる                                                  | 返信の作成が成功する                                         | 合   |
| Worker が実 PDS のレコードの CID を再計算して照合できる                     | 再計算した CID が作成時の CID と一致する                     | 合   |
| 作成したレコードを第三者が公開 API で読み出せる                             | 6 件すべてを認証なしで取得できる                             | 合   |
| 作成したレコードと投稿を後始末で削除できる                                  | 6 件すべてが削除後に取得できない                             | 合   |
| ブラウザの OAuth で実アカウントにサインインし、要求した権限で書き込める     | task・progress・投稿の作成が成功する                         | 合   |
| ブラウザの OAuth で、要求していないコレクション・操作・画像以外が拒否される | bot.receipt の作成・delete・text/plain の blob が 403 になる | 合   |
| ブラウザの OAuth で作成した実レコードを Worker が CID 照合できる            | 再計算した CID が作成時の CID と一致する                     | 合   |
| Bot の返信がユーザーの通知として届く                                        | listNotifications に reason=reply が現れる                   | 合   |
| 返信を連ねると 1 つのスレッドになる                                         | 起点→返信 1→2→3 の入れ子で取得できる                         | 合   |
| 日本語の文面でリンクの facet が正しく付く                                   | byteStart・byteEnd の範囲が URL と一致する                   | 合   |
| refreshJwt でセッションを更新できる                                         | 更新に成功し、新しいトークンを得る                           | 合   |
| 同じ rkey の二重作成が拒否される                                            | 並列でも 1 件だけ成功する                                    | 合   |
| 受理時刻をコミットの rev で固定できる                                       | createdAt を詐称しても rev は実時刻に近い                    | 合   |
| 受理後の更新・削除を検出できる                                              | 更新で CID が変わり、削除で RecordNotFound になる            | 合   |
| 公開 HTTPS のクライアント情報で OAuth が通る                                | 認可・書き込み・CID 照合が成功する                           | 合   |
| result を含む権限で書き込める                                               | result の作成が成功する                                      | 合   |
| PDS の blob を別オリジンの画面で表示できる                                  | img の表示と CORS の取得が成功する                           | 合   |
| 再読み込みで OAuth のセッションを復元できる                                 | 再読み込み後もサインインが保たれる                           | 合   |
| jpeg と webp の画像を blob として保存できる                                 | 約 1 メガバイトの画像のアップロードが成功する                | 合   |
| PDS が宣言と異なる形式を判別する                                            | image/png と宣言した jpeg が image/jpeg になる               | 合   |
| 同じ確認依頼への並列な受理を 1 件に絞れる                                   | 30 並列で挿入が 1 件だけ成功する                             | 合   |
| 本番の Cron Trigger が発火して処理が空の実行が軽い                          | 発火し CPU 時間が 1 ミリ秒未満である                         | 合   |
