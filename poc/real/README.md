# 実アカウントでの受理フロー PoC

## 1. 結論

bsky.social 上の実アカウント 2 つ（ユーザーと Bot）で、起点投稿・作業・確認依頼・進捗報告・受領証の作成から、Worker での CID 照合、削除までが成功する。ブラウザの OAuth でも、要求した権限だけが付与され、要求していない操作は拒否される。

## 2. 反映先

- receipt

## 3. 制約値

| 項目                                                | 値            |
| --------------------------------------------------- | ------------- |
| 実環境での受理 1 回の外部通信の所要時間（DID 解決） | 約 730 ミリ秒 |
| 実環境での受理 1 回の外部通信の所要時間（取得）     | 約 400 ミリ秒 |
| 実環境での CID 計算の所要時間                       | 約 1 ミリ秒   |

## 4. 検証項目

| 仮説                                                                        | 合格基準                                                     | 結果 |
| --------------------------------------------------------------------------- | ------------------------------------------------------------ | ---- |
| 実 PDS 上の独自コレクションにユーザーと Bot がレコードを作成できる          | 作業・進捗報告・確認依頼・受領証の作成が成功する             | 合   |
| Bot が起点投稿へ返信できる                                                  | 返信の作成が成功する                                         | 合   |
| Worker が実 PDS のレコードの CID を再計算して照合できる                     | 再計算した CID が作成時の CID と一致する                     | 合   |
| 作成したレコードを第三者が公開 API で読み出せる                             | 6 件すべてを認証なしで取得できる                             | 合   |
| 作成したレコードと投稿を後始末で削除できる                                  | 6 件すべてが削除後に取得できない                             | 合   |
| ブラウザの OAuth で実アカウントにサインインし、要求した権限で書き込める     | task・progress・投稿の作成が成功する                         | 合   |
| ブラウザの OAuth で、要求していないコレクション・操作・画像以外が拒否される | bot.receipt の作成・delete・text/plain の blob が 403 になる | 合   |
| ブラウザの OAuth で作成した実レコードを Worker が CID 照合できる            | 再計算した CID が作成時の CID と一致する                     | 合   |
