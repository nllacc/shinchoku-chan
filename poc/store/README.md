# 保存先の契約 PoC

## 1. 結論

D1 は、1 回の batch で数百行の書き込みと複数の読み出しを 1 往復で行え、保存先の契約の実装に使える。束縛変数は 1 クエリ 100 個までのため、getMany は 100 個ずつに分ける。表の挿入は索引の数に 2 を足した行を書くため、行の書き込み数は索引の少なさで決まる。

## 3. 制約値

| 項目                                    | 値      |
| --------------------------------------- | ------- |
| 1 クエリの束縛変数                      | 100 個  |
| 索引 3 つの表への挿入で書く行数         | 5 行    |
| 既存行への INSERT OR REPLACE で書く行数 | 5 行    |
| 既存行への upsert で書く行数            | 4 行    |
| 索引のない列の更新で書く行数            | 1 行    |
| 索引のある列の更新で書く行数            | 2 行    |
| 1 回の batch に入れた文の数             | 1000 件 |
| 一覧 1 ページ（51 件）の読み取り行数    | 52 行   |

## 4. 検証項目

| 仮説                                                       | 合格基準                                               | 結果 |
| ---------------------------------------------------------- | ------------------------------------------------------ | ---- |
| 複数行の書き込みを 1 往復で行える                          | 1000 件の batch が成功し、20 件の batch が逐次より速い | 合   |
| getMany を 1 つの IN 句で行える                            | 101 個以上の IN 句が成功する                           | 否   |
| putIfAbsent を挿入と読み出しの batch で実現できる          | 20 並列の呼び出しがすべて同じ計画を得る                | 合   |
| 存在しない主キーの patch が例外にならない                  | 更新件数が 0 で成功する                                | 合   |
| 行値比較のキーセットで一覧を重複なく送れる                 | 同点を含む 270 件を 51 件ずつ読んで重複と欠落がない    | 合   |
| 一覧 1 ページの読み取りが 60 行以下                        | 読み取り行数が 60 以下                                 | 合   |
| 期限の来た対象がないときの読み取りが 1 行以下              | 索引つきの検索の読み取り行数が 1 以下                  | 合   |
| 索引のない列の更新は 1 行、索引のある列の更新は 2 行である | 書き込み行数が 1 と 2 になる                           | 合   |
