# 受信 PoC

## 1. 結論

Bot は通知の取得だけで、ユーザーのメンションと評価の返信を数秒で受け取れる。無料枠の Worker は毎分の Cron Trigger で起動でき、受信用の常駐サーバーは要らない。

## 2. 反映先

- なし

## 3. 制約値

| 項目                                       | 値                       |
| ------------------------------------------ | ------------------------ |
| メンション投稿が Bot の通知に現れるまで    | 約 5.7 秒                |
| 返信が Bot の通知に現れるまで              | 約 5.9 秒                |
| 無料枠での Cron Trigger の発火間隔（実測） | 60 秒、CPU 時間 0 ミリ秒 |
| 無料枠の Cron Trigger の数                 | 1 アカウントあたり 5 個  |
| 無料枠の 1 回の実行あたりの外部通信の上限  | 50 回                    |
| 無料枠の 1 回の実行あたりの CPU 時間の上限 | 10 ミリ秒                |

## 4. 検証項目

| 仮説                                                           | 合格基準                                             | 結果 |
| -------------------------------------------------------------- | ---------------------------------------------------- | ---- |
| ユーザーが Bot をメンションした投稿が、Bot の通知に現れる      | reason が mention の通知に、その投稿が現れる         | 合   |
| メンションの通知が 10 秒以内に現れる                           | 投稿から通知の取得までが 10 秒以内                   | 合   |
| 通知から本文・投稿者の DID・時刻を取り出せる                   | 本文・DID・indexedAt が投稿と一致する                | 合   |
| メンションの facet が Bot の DID を指す                        | facet の DID が Bot の DID と一致する                | 合   |
| reasons の指定で、mention と reply だけを取得できる            | 取得した通知の reason が mention か reply だけである | 合   |
| Bot の返信がメンション付きでユーザーに届く                     | ユーザーの通知に Bot の返信が現れる                  | 合   |
| ユーザーの返信が reply として Bot の通知に現れる               | reason が reply の通知に、その返信が現れる           | 合   |
| 返信の親から、評価の対象にした Bot の投稿を特定できる          | reply.parent の URI が Bot の投稿と一致する          | 合   |
| 通知が新しい順に並び、取得位置の保存に indexedAt を使える      | indexedAt が降順に並ぶ                               | 合   |
| 無料枠の Worker が毎分の Cron Trigger で起動し、空の実行が軽い | 毎分発火し、CPU 時間が 1 ミリ秒未満である            | 合   |
